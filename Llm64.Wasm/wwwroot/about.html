What is this?

This little webapp takes a PNG, and adds a blob of binary data to it. The fun part is that when that blob of data is shown in base64 encoding, text shows up. This doesn't change what the image looks like when it's viewed, the text is entirely ignored by most (hopefully all) browsers and tools.

However, if you were to attach this PNG file to an email, then the way email attachments are done means that the text might be visible in the raw email body. Which is fun, right?!

Ok, how does it work?

We take advantage of a few things.

  • PNG files allow us to add our own blocks of data without affecting the image itself
  • base64 encodes data by converting bytes to the ascii characters A..Z, a..z, 0..9 as well as + and /
  • email programs put attachments in MIME message bodies (blocks of text separated by dividers)
  • RFC 2045 says that base64 attachments are in lines of characters exactly 76 characters long

So let's say we want to display the text "1000 words" when our image is encoded in base64. Our first problem is that base64 doesn't allow spaces, but maybe we're ok with "1000+words".

We first need to work out what bytes encode to that base64 string. That's easy enough, since 3 bytes is encoded as 4 base64 characters. (3 * 8 bits = 24 bits of data) Then each of the 64 valid base64 characters represents 6 bits of data (2 * 6 bits = 24 bits). So 3 bytes in the input becomes 4 characters in the output.

Which means to show "1000+words" in the end, we need the bytes d7 4d 34 fb 0a 2b 76 to appear in the PNG (play around here to see more).

Of course, it's not quite that simple and we need to deal with byte offsets and so on to make sure our text always shows up, but that's just details.

Are you stealing my pictures?

No, i don't want your pictures. In fact, i never see them. This webapp is a blazor WASM application, originally written in dotnet and built to run in your browser. Nothing ever leaves your browser unless you want it to. I don't even run analytics on this site (though it's hosted on AWS so I guess there are some s3 access logs somewhere I never look at)

What are the implications?

Nothing! This was just for fun after a discussion with a colleague whether it might be even possible to make base64 blobs look readable. There's certainly no poorly coded systems out there which might be hooked up to read emails and take actions on things they see. No siree I'm sure they're all keeping the attachments and the content well and truly isolated from each other.
